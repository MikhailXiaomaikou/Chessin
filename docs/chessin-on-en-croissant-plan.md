## 0. 一页结论

**EC 能当底座。** 代码量小（约 3.3 万行 TypeScript、8.8 千行 Rust），技术栈现代（Tauri 2、React 19、Rust、SQLite），类型安全的前后端通信已经就位。棋盘、着法树、多引擎分析、PGN 导入、开局体系训练、谜题、Lichess 和 Chess.com 同步都可以直接沿用。按拆解文档第 3.3 节的 ChessBase 功能清单算，EC 已覆盖大约四成。

**但 EC 不能直接发给用户。** 有三类问题必须先解决：

1. **分叉阻断项**：更新器指向 EC 的服务器并用 EC 的签名公钥（不改，Chessin 会被"更新"成 En Croissant）；遥测默认开启并发往 EC 的 PostHog 项目；引擎、对局数据包、谜题包的目录都从 encroissant.org 下载且不校验。✅
2. **数据安全**，这是 EC 最弱的一环：自动保存默认开启，每走一步都写回源文件，包括用户的大师库；没有撤销；标签页和分析只存在会话存储里，退出就丢；删除不可逆；导入时关闭了 SQLite 日志，崩溃会损坏库。✅ 这些正是 ChessBase 被抱怨"丢数据"的同类问题。
3. **规模**：局面检索是全库暴力回放，100–200 万盘以内够用，到 Mega 的千万盘级每走一步要等几秒到几十秒（估算，未实测）。没有名字规范化，没有任何 ChessBase 格式读取器。

**EC 还原样复刻了 ChessBase 的两个体验问题：** 隐藏的"参考数据库"标记不设置就让探索器、新着检测、开局体系覆盖率静默失效；数据库和棋盘是两条路由，打开一盘棋就丢掉列表上下文。

**做法：软分叉加覆盖层。** EC 的 Rust 内核和分析面板保持原样跟随上游；Chessin 的新东西全部放在独立位置（独立 Rust crate、`src/chessin/`、独立的翻译命名空间、配置覆盖文件）。通用修复先合进 Chessin，再向上游提 PR。等单窗口工作区（IA-1）落地后，外壳层接受硬分叉，内核继续跟随上游。

**顺序：先安全，再闭环，再补数据能力，最后深度。**

| 阶段           | 周    | 目标                                                                               |
| -------------- | ----- | ---------------------------------------------------------------------------------- |
| S0 分叉卫生    | 0–2   | 以 Chessin 身份安全发版，不再碰 EC 的基础设施                                      |
| S1 安全与上手  | 2–8   | 永不丢数据、中文术语、命令面板、来源芯片、首次启动、读个人 CBH 库                  |
| S2 闭环 A 内测 | 6–14  | 导入 → 复盘 → 错题本（拆解文档的 MVP），200 名中文用户内测                         |
| S3 v1 公测     | 12–26 | 千万盘级局面索引、查找相似、芯片检索、大师来源、2CBH、开局体系工作台、单窗口工作区 |
| S4 v1.x        | 26–40 | 备战简报、开局体系维护、统一训练队列、深度分析、可核验讲解接 LLM、教练作业         |

**第一周必须做的事**：换更新器密钥和端点、删掉 PostHog、目录改成自建并校验、换应用标识和深链、注释渲染加消毒、收紧 CSP 和文件权限、审计棋子素材的许可证。清单见附录 A。

**已经拍板的事**（详见第 9 节）：项目完全免费开源，不收费；外壳在 S3 硬分叉；CBH 读取器净室实现；应用标识 `cn.chessin.app`，更新和目录先托管在 GitHub，国内镜像待实测后再加；不做遥测。**仍是假设：** 团队规模和时间。

### 1.3 EC 与 ChessBase 问题的对照

拆解文档第 5 节列了 ChessBase 的 14 个体验问题。EC 的情况：

| ChessBase 问题          | EC 的情况                                                                   |
| ----------------------- | --------------------------------------------------------------------------- |
| #4 丢数据、替换式保存   | **更差**：自动写回源文件、无撤销、会话存储、日志关闭                        |
| #9 隐藏配置导致静默失效 | **原样复刻**：`referenceDbAtom`                                             |
| #5 多窗口、功能埋得深   | 一半解决：单窗口，但数据库和棋盘仍是两条路由；没有命令面板                  |
| #1 上手难               | 部分解决：没有激活、没有 Ribbon；但首次启动总是英文、没有引擎、没有导入引导 |
| #3 只有 Windows         | 已解决：三平台                                                              |
| #2 #10 购买组合、激活   | 已解决：免费开源                                                            |
| #6 开局体系繁琐         | 一半解决：有覆盖率概念，但依赖参考库，没有等级分区间和概率加权              |
| #7 复盘只有引擎注释     | 相同：报告以准确率为标题，只加 NAG 和变着                                   |
| #12 教学协作            | 没有                                                                        |
| #13 无障碍              | **更差**：焦点框被全局去掉                                                  |
| #14 迁移锁定            | 不读任何 ChessBase 格式                                                     |

结论：**EC 解决了平台和价格问题，没有解决数据安全和"隐藏配置"问题，后两者要由 Chessin 来修。**

## 2. 分叉策略

**原则：** 软分叉加覆盖层。EC 文件只做"挂载点"级改动；Chessin 的代码全部放在独立位置；通用修复回馈上游以缩小差异；外壳在 IA-1 落地后硬分叉。

### 2.1 仓库与分支

- Chessin 仓库导入 EC 完整历史，远端命名 `upstream`。`main` 用合并提交（merge，不用变基 rebase）**按月**合入上游。上游每月约 7 个提交，且 5–8 月为零，按月足够。
- CI 增加一个每周任务：自动演练合并 `upstream/main`，跑 lint 和测试，提前暴露冲突。
- 发版列车自己掌握。上游 29 个提交未发版，Chessin 的修复不等上游。

### 2.2 代码分层

| 层             | 位置                                                                                                                                                                                                                                                                                                                                                                                  | 规则                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **配置覆盖**   | `src-tauri/tauri.chessin.conf.json`，构建时 `tauri build --config` 合并                                                                                                                                                                                                                                                                                                               | 覆盖 identifier、productName、deep-link scheme、更新器公钥和端点、CSP。`tauri.conf.json` 本身与上游逐字节一致                                           |
| **Rust 新增**  | `src-tauri` 改成 Cargo workspace，新增 `crates/chessin-*`，以 `tauri-plugin-chessin` 注册，自带 tauri-specta 导出到 `src/chessin/bindings.ts`                                                                                                                                                                                                                                         | `main.rs` 只加一行 `.plugin(...)`，不碰冲突热点 `collect_commands!`                                                                                     |
| **前端新增**   | `src/chessin/**`；新路由用 TanStack 文件路由自动生成                                                                                                                                                                                                                                                                                                                                  | 不手工合并 `routeTree.gen.ts`                                                                                                                           |
| **翻译**       | 独立命名空间 `chessin`，文件 `src/chessin/i18n/{zh-CN,en-US}.json`，独立的 i18next-cli 配置                                                                                                                                                                                                                                                                                           | 避开上游 `removeUnusedKeys: true` 和 16 个语言文件的高频变动；EC 已有 key 的中文修正直接给上游提 PR                                                     |
| **数据**       | `app-data/chessin/library.sqlite`：工作区、版本、回收站、复习卡、评估缓存、别名、来源、设置。对局库仍是 EC 格式的 `.db3`，新增内容放 `.db3` 内的 `chessin_*` 表（各自带迁移）和旁路索引文件（`.cpi`）                                                                                                                                                                                 | EC 仍能打开 Chessin 的库                                                                                                                                |
| **挂载点台账** | 为接入 Chessin 新模块而改的上游文件只允许这些：`main.rs`、`Cargo.toml`、`src/utils/tabs.ts`（标签类型枚举）、`BoardsPage.tsx`（TabSwitch 委托给注册表）、`Sidebar.tsx`（导航注册表）、`BoardAnalysis.tsx`（停靠栏插槽）、`__root.tsx`（挂载面板、状态栏、首启页）、`atoms.ts`（默认值）、`index.tsx`（语言检测）、`App.tsx`（去掉 PostHog 和更新器）、`DatabasePanel.tsx`（来源芯片） | 每处改动写明原因。上游 bug 修复另记"回馈台账"（附录 B），每条必须对应一个已提或待提的上游 PR，合入后在本地删除差异。两张台账之和在 S2 结束时少于 600 行 |

### 2.3 文件三分法

- **自有（S3 起不再自动合并，上游改动人工移植）**：`src/routes/*`、`Sidebar.tsx`、`TopBar.tsx`、`tabs/{BoardsPage,BoardTab,NewTabHome,ConfirmChangesModal}.tsx`、`DatabasesPage.tsx`、`FilesPage.tsx`、`keybinds.ts`，以及 `atoms.ts` 中标签页、会话、参考库、自动保存的几段。`BoardAnalysis.tsx`、`BoardGame.tsx`、`Puzzles.tsx` 的布局容器部分自 S3 起转为自有（IA-1 去 Portal），其内部的棋盘、记谱、面板子组件仍跟随上游。
- **跟随（保持最小差异，修复做成可上游的 PR）**：`src-tauri/src/{db,engine}/*`、`chess.rs`、`game.rs`、`pgn.rs`、`puzzle.rs`、`opening.rs`、`src/utils/*`、`components/{boards,common,panels,puzzles}/*`、数据库表格组件。
- **新增**：`src/chessin/**`、`src-tauri/crates/chessin-*`、`services/*`。

### 2.4 硬分叉边界与退出条件

- S3 用 IA-1 替换 `BoardsPage` 和 Portal 布局之后，外壳文件正式硬分叉。内核继续合并（merge）或只挑选单个提交合入（cherry-pick）。
- 每季度评估：如果每月合并上游的成本超过 2 个工程师日，就改为只 cherry-pick。

### 2.5 数据格式策略

- `.db3` schema **只增不改**：新表、可空新列、FTS 虚表，用 `PRAGMA user_version` 做迁移；升级前先备份。EC 的 Diesel 查询写死了列名，所以 EC 仍能读核心表。
- 着法编码沿用 `encoding.rs`，但它存的是 shakmaty `legal_moves()` 的序号，shakmaty 升级改变走法顺序会静默损坏全部数据。**锁定 shakmaty 0.27.1，加黄金向量测试，v1 不改格式。** 索引里的着法用与局面无关的 16 位编码。
- 用户的外部文件（PGN、`.db3`、挂载的 CB 库）默认只读。

### S0 分叉卫生与护栏（第 0–2 周，部分与 S1 并行到第 4 周）

目标：拿到一个可分发、不碰 EC 基础设施、能持续合并上游的 Chessin 构建，并搭好覆盖层骨架。

**第 0–2 周必做：**

- 配置覆盖（identifier、productName、deep-link；更新器先停用，自有 minisign 密钥生成后再指向 GitHub Releases；CSP）；删除 PostHog，不做遥测；目录改为可配置并指向 Chessin 仓库的 `catalog/`；`fs.rs` 下载流式写盘、断点续传、sha256 校验；`oauth.rs` 的 Lichess client_id 改为 Chessin 标识；翻译文件产品名改用 `{{appName}}` 插值。
- 安全边界：`Comment.tsx` 去掉原始 HTML 渲染；收窄 assetProtocol、fs、opener 的范围；深链导入前先确认。
- Cargo workspace、`tauri-plugin-chessin` 空壳、`src/chessin/`、`chessin` 翻译命名空间、挂载点台账（`docs/seams.md`）。
- CI：cargo test、clippy（fmt 门禁等上游代码格式化后再加，否则一合入就红）；bindings 漂移检查；每周上游合并演练。
- 素材许可审计，剔除 NC 素材；把 `vampirc-uci` 的 git 依赖复制进仓库（vendor）。
- 第 0 周即启动 Windows 代码签名证书和 Apple 开发者账号申请（周期通常 2–4 周）。
- 首批上游 PR：符号导出、`Comment.tsx` 消毒、`search.rs` 的 `finished` 事件、WAL。
- 产品：ChessBase'26 实机走查录屏；8–12 人访谈；大陆网络可达性实测；对象模型和术语表 v0 定稿。

**第 2–4 周，与 S1 并行：**

- 签名与公证接入 release。
- 冒烟测试：Linux 和 Windows 在 CI 用 tauri-driver 跑 10 条（打开 PGN、走子、开引擎、导入、谜题、浏览库）；macOS 只做人工冒烟（tauri-driver 不支持 macOS）。
- 回归语料：PGN 边界样本、个人 CBH、俄文库、中文名库；保真度回归另用本地购买的 Mega 2026 抽样，不进 CI。基准语料：Lichess 开放数据库（CC0）抽样 200 万盘和 1000 万盘，加 TWIC 近年包；criterion 基准跑 `search.rs`、`convert_pgn`。
- 索引方案技术验证（spike）：自研段文件对比 tantivy，200 万盘出原型；1000 万盘在 S1 期间跑通。

**出口：** 可安装的内测包能与 EC 并存（签名在证书到位后补齐，最晚第 4 周）；抓包确认没有任何请求发往 encroissant.org 或 posthog；CI 跑 Rust 测试；上游合并演练无冲突；索引技术验证在 200 万盘上精确查询 p50 <100 ms（第 4 周）。

### S1 数据安全、中文与上手（第 2–8 周）

目标：把 EC 的数据安全和中文问题修到能给真实用户用；补上命令面板、来源芯片、首次启动和个人 CBH 导入。

- X-3 核心：工作区和着法树持久化到 `library.sqlite`，崩溃恢复；稳定节点 ID；immer patch 撤销和重做；外部来源默认只读；回收站；"清除数据"改为分项重置；EC→Chessin 迁移器（设置、键位、牌组、引擎、库路径、账号）。
- 修 `EvalListener` 和威胁模式；翻转棋盘不再写表头；PGN 符号和注释序列化修复，补往返测试；保留全部表头。
- X-7：`terms.yaml`；补空值和术语冲突；lint 禁止字面量字符串；语言跟随系统；dayjs 中文；开局名中文列。
- IA-2 命令面板（拼音、粘贴识别）；作用域键位加输入法守卫；`?` 速查；ChessBase 预设。
- IA-3 v0：来源芯片取代 `referenceDbAtom`；Lichess Masters 免登录、单请求队列、429 后退避 60 秒，作为没有本地库的用户的默认来源；`db_cache` 按路径缓存；`line_cache` 改 LRU 并在写入后失效。
- W0-1 首次启动一屏。
- W0-2 v0：`chessin-cb` 读 CBH v1 个人库，导入报告。
- 状态栏 v0；焦点框和 aria-label 基础；错误页和反馈渠道。

**出口：** 16 人可用性测试（拆解文档 8.3 的 6 个任务）：新用户独立完成至少 5 项；个人 CBH 语料的文字、NAG、变着保真度 ≥99%；zh-CN 冒烟测试无残留英文；写入中强杀 1 万次库损坏 0 次；`kill -9` 后丢失的编辑不超过最近 500 ms；崩溃会话恢复率 ≥99.9%（自动化测试，与拆解文档 X-3 验收一致）。

### S2 闭环 A 内测：导入 → 复盘 → 错题本（第 6–14 周）

目标：交付拆解文档 8.6 的 MVP，只依赖用户自己的对局和本地引擎。E1 从第 8 周起转做局面索引。

- `chessin-core` 任务服务、全局引擎池、持久评估缓存；最小任务中心。
- 导入或同步后自动后台复盘：关键时刻按期望得分下降 × 可找到性（启发式：最佳着与次佳着的差、首次找到的深度、是否显眼着）排序；先自己再试一次；分阶段损失；时间压力标记；"失误检查"作为复盘预设：只标败着、重跑替换不叠加。
- X-1 v0：确定性检测器加中英模板句，一键在棋盘上演示，标证据等级；不接 LLM。
- 为 IA-1 做准备（E3）：把棋盘、记谱、引擎和探索器面板抽成不依赖路由和 Portal 的纯组件，每种标签类型一个 PR；提供 `openInWorkspace()` 兼容层并替换现有 `navigate('/')` 调用点；旧路由用功能开关保留到 S3 结束。
- W5-1 错题本（找着卡）；复习库迁到 SQLite，EPD 为键，迁移旧牌组；"今天"卡先挂在 EC 现有的 `NewTabHome`（已列为自有文件），S3 随 IA-1 迁入新主页；启动后自动增量同步账号并合并为"我的对局"。
- 分叉条件：如果立项前访谈显示需求主要由教练和机构驱动，本阶段改为 W6-1 最小版加错题本。最小版的定义：教练端导出带作业说明的 PGN 并生成分享链接；学生端是纯静态网页（棋盘、走子、作答），提交以 PGN 文件或链接回传；不做账号、班级码和批改收件箱（放 S4）。代价：自动复盘降为手动触发，"今天"卡和账号自动同步顺延到 S3。

**出口：** 内测包最晚第 10 周发出，200 名中文内测用户；4 核笔记本上一盘 40 着的棋从导入到复盘就绪 ≤3 分钟；从安装到自己的棋上盘并有评估中位 <3 分钟；第 14 周看次周留存 ≥40% 和错题本 14 日留存；错题本 30 日留存 ≥25% 作为第 18 周的复核门槛，不达标则 S3 暂停扩功能。留存以内测群人工统计和自愿问卷为口径（不做遥测）。没有丢数据报告。IA-1 准备完成：棋盘、记谱、面板已纯组件化，冒烟测试通过。**不达标就继续改闭环 A，不扩功能。**

### S3 v1 公测：补齐 ChessBase 强项（第 12–26 周）

目标：千万盘级本地检索、查找相似、统一检索、大师来源、2CBH、开局体系工作台、单窗口工作区。本阶段外壳正式硬分叉。

- `chessin-index`（倒排加树聚合加签名文件），探索器直接查索引，暴力回放降为核验路径。
- 统一 `GameQuery`：表头位图、FTS5 注释、局面；芯片查询栏；结果集合与智能棋谱集。

## 8. 不做的事

- 不重写 EC 的棋盘、着法树、引擎内核和状态库；不换 SQLite；只新增 crate。
- 不改 `.db3` 着法编码，不升级 shakmaty（v1）。
- 不写回 CBH、2CBH；不打包写出 CBV；不破解 CBZ、不内置密钥；不碰 ChessBase 激活。
- 不对接 Let's Check、LiveBook、Engine Cloud、Remote Engine 的私有协议；不做众包评估上传。
- 不做 Mega 式的人工编辑数据库和人工注释；不分发或批量抽取 Mega；不在用户挂载的商业库上训练模型。
- 不做 Ducats 代币、按分钟计费、算力市场、对弈服务器、硬件激活；不给本地功能上锁。
- 不静默匹配对手的网络账号；不侦察未成年人。
- 不给 AI 结论配一句免责声明了事：没经引擎或残局库核验的战术论断不显示。
- 不设新手模式和专家模式；默认不做多窗口；不做 Ribbon。
- 公测前不做 Web 端、移动端、账号体系（W6-1 的学生网页除外：最小版最早 S2，完整版 S4）；不做记录纸拍照识别和对局中的记录模式。
- 不维护 EC 另外 14 种语言的 Chessin 新增文案；`chessin` 命名空间只做 zh-CN 和 en-US，其他语言回退英文。
- 不上架 Mac App Store（与 GPL 不兼容）。
- 不链接 AGPL 代码。
- 不用单一的"准确率%"当复盘标题。
